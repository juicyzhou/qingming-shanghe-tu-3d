# 我用纯程序化生成，做了一座可以走进去的《清明上河图》

> 一个三人份的周末项目？不，一个人的：0 个模型、0 张贴图、0 段音频，
> 约 4860 行 JavaScript，在浏览器里长出一座北宋汴京。打开就能玩，
> 还能走、能聊、能接任务。

**在线体验**：<https://juicyzhou.github.io/qingming-shanghe-tu-3d/>

---

## 一、为什么要"纯程序化"

《清明上河图》的街景极其丰富：虹桥、汴河、货船、酒肆茶楼、车马行人……
如果逐个建模、逐张找贴图、逐段录音频，这个规模的项目要么工期爆炸，要么资源包巨大。

于是定下一条铁律：

> **零外部资源文件。所有模型、贴图、音频，全部在运行时由代码生成。**

好处很直接：

- **体积**：整个游戏打包后约 641KB（gzip 172KB），一个 HTML + 一个 JS。
- **部署**：没有跨域、没有 CDN 依赖、没有字体/贴图路径问题，丢到任意静态托管就能跑。
- **可玩性**：因为是代码生成，48 位宋人的外貌、10 家店铺的布局、BGM 的音符，
  全部可以参数化随机——每次打开世界都有细微差别。

| 模块 | 方案 | 说明 |

| 渲染 | **three.js r170** | 场景/相机/几何/着色器 |

## 三、几个关键技术点

### 1. Toon 手绘风着色器

国画感的核心不是模型精细，而是**光影被"量化"成几个色阶**：

```glsl
float ndl = max(dot(n, uSunDir), 0.0);
float d = floor(ndl * 3.0 + 0.55) / 3.0;   // 三档明暗
d = max(d, 0.15);                            // 暗部保底，不压成死黑
vec3 col = uAmbient * (1.0 + uBoost) + uSunColor * d;
col = 1.0 - exp(-col * 1.5);                 // 柔和压缩，防过曝发白
```

配合边缘光、手动雾效、暖色后处理，远处褪色近处清晰，还原画卷的远近层次。

### 2. Canvas 贴图：一块"布幌"就是几行画布命令

店幌上的"酒""茶""药"是直接写进 Canvas 的文字；人脸是一套参数化绘制
（肤色/眉眼/胡须/皱纹随机组合）；屋顶瓦片是循环画弧。于是：

- 48 位 NPC 没有一位长相相同（肤色×发型×胡须×帽×衣色的组合空间极大）
- 改一个字、调一个色，改代码即可，不用重导美术

### 3. Web Audio 合成音乐

古风 BGM 不用任何音频文件——用振荡器 + 包络模拟"筝/琵琶"的拨弦：

```js
osc.frequency.setValueAtTime(freq * 1.01, t);
osc.frequency.exponentialRampToValueAtTime(freq, t + 0.03); // 起音滑音
gain.gain.exponentialRampToValueAtTime(vol, t + 0.012);      // 快速点亮
gain.gain.exponentialRampToValueAtTime(0.0001, t + dur);     // 衰减
```

宫商角徵羽五声音阶循环 + 低音铺底 + 稀疏高音点缀，汴河的烟火气就有了。
环境音同理：汴河低频水声、市井带通人声、随机清脆鸟鸣，三层叠起来，
"听觉上"也是一座活的汴京。

### 4. 性能：把 draw call 从 2588 压到 812

纯程序化最容易爆的是**网格数量**。优化三板斧：

- **几何合并**：同一材质的建筑部件合并成一个 BufferGeometry（每栋店 ~40 → 8）
- **实例化**：70 棵柳树/松柏用 InstancedMesh（360 → 4）
- **距离剔除 + 自适应分辨率**：远处 NPC 隐藏、帧率低时自动降渲染分辨率

出生街景可见 draw call 从 ~2588 降到 ~812，三角面约 10.6 万。

### 5. 可玩性：任务系统让"看画"变成"入画"

不只是看，还能玩：8 条任务线（送烧饼、买茶叶、采药草、撑船过桥、
城门传话……）、对话分支、背包与经济、节奏小玩法、成就分享卡。
靠近带"?"的人按 E 交谈，接任务后屏幕边缘会出现方向箭头和距离，
玩家永远知道自己该去哪。

## 四、踩过的坑（真实 GPU 上的教训）

1. **无头渲染 ≠ 真机**。部分伪影只在真实 GPU 出现，必须用"用户截图 + 真机调试射线"
   定位。曾排查数轮的"凭空出现的灰蓝平面"，最终定位为第一人称低头看到自己角色的
   长袍挡视线——第一人称隐藏自身身体是行业默认。
2. **方向/坐标约定要一次定死**。`右向量 = 前向 × 上向`，曾因推导错误两度返工，
   现在代码顶部写死注释。
3. **透明度要手动处理**。ShaderMaterial 需自己写 alpha，否则透明通道深度排序
   会闪烁、消失。
4. **后处理读回在软件渲染下不可靠**，会出假"反光/灰蓝"，需用真实浏览器截图交叉验证。
5. **无音频设备的环境**：AudioContext.currentTime 可能是 NaN，调度前用
   `isFinite()` 防御，否则直接崩。
